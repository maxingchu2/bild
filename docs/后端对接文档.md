# 后端对接文档（Java 版）

本项目前后端通过 **一个接口** 解耦：`POST /api/chat`。只要 Java 后端按本文档实现同样的请求/响应契约，前端页面（`static/index.html`）**无需任何修改**即可直接对接，功能保持不变。

```
浏览器(static/index.html)  ──POST /api/chat──▶  后端(FastAPI 或 Java)  ──▶  大模型(OpenAI 兼容接口，如 DeepSeek)
        ◀───────── SSE 流式返回 ─────────────
```

## 一、接口契约

### 1. 请求

- 方法/路径：`POST /api/chat`
- Content-Type: `application/json`

```json
{
  "messages": [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好！有什么可以帮你？"},
    {"role": "user", "content": "写一段快排"}
  ],
  "max_tokens": 2048,
  "temperature": 0.7
}
```

说明：
- `messages`：完整多轮对话历史（前端自己维护并每次全量发送），`role` 取 `user` / `assistant` /（可选）`system`。
- `max_tokens`、`temperature` 可选，有默认值。

### 2. 响应（SSE 流）

- 响应头：`Content-Type: text/event-stream`，建议加 `Cache-Control: no-cache`、`X-Accel-Buffering: no`（经 nginx 时防缓冲）。
- 每个事件为一行 `data: <JSON>`，后跟一个空行（`\n\n`）。

事件类型（JSON 字段三选一）：

| 事件 | 含义 |
|---|---|
| `data: {"reasoning": "增量思考文本"}` | 推理模型的思考过程（可选，非推理模型没有） |
| `data: {"content": "增量正文文本"}` | 回答正文的 Markdown 增量 |
| `data: {"error": "错误信息"}` | 出错时发送 |
| `data: [DONE]` | 流结束标志（固定字符串，必须发送） |

示例流：

```
data: {"reasoning": "用户想要"}

data: {"reasoning": "快排……"}

data: {"content": "```python"}

data: {"content": "\ndef quick_sort"}

data: [DONE]
```

### 3. curl 自测

```bash
curl -N http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"messages": [{"role": "user", "content": "你好"}]}'
```

## 二、上游大模型调用（后端内部）

后端收到请求后，转发到 OpenAI 兼容的 chat completions 接口（当前为 DeepSeek）：

- URL：`https://api.deepseek.com/v1/chat/completions`
- Header：`Authorization: Bearer <API_KEY>`
- Body：在前端传来的 `messages` 基础上加 `"model": "deepseek-v4-flash"` 和 `"stream": true`

上游返回标准 OpenAI SSE 流，每个 chunk 形如：

```json
{"choices": [{"delta": {"content": "文本增量", "reasoning_content": "思考增量"}}]}
```

后端要做的事：逐行读取上游 SSE → 取出 `delta.content` / `delta.reasoning_content` → 按第一节的格式转发给前端 → 收到 `[DONE]` 后给前端发 `data: [DONE]`。

## 三、Java（Spring Boot）实现示例

### 依赖（WebFlux 方式，推荐）

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>
```

### DTO

```java
public record ChatMessage(String role, String content) {}

public record ChatRequest(List<ChatMessage> messages,
                          Integer maxTokens,
                          Double temperature) {}
```

### Controller（SSE 透传）

```java
@RestController
public class ChatController {

    private static final String UPSTREAM_URL = "https://api.deepseek.com/v1/chat/completions";
    private static final String API_KEY = System.getenv().getOrDefault("UPSTREAM_API_KEY", "sk-xxx");
    private static final String MODEL = "deepseek-v4-flash";

    private final WebClient client = WebClient.builder().baseUrl(UPSTREAM_URL).build();
    private final ObjectMapper mapper = new ObjectMapper();

    @PostMapping(value = "/api/chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<String> chat(@RequestBody ChatRequest req) {
        Map<String, Object> payload = Map.of(
                "model", MODEL,
                "messages", req.messages(),
                "max_tokens", req.maxTokens() == null ? 2048 : req.maxTokens(),
                "temperature", req.temperature() == null ? 0.7 : req.temperature(),
                "stream", true);

        return client.post()
                .header("Authorization", "Bearer " + API_KEY)
                .contentType(MediaType.APPLICATION_JSON)
                .bodyValue(payload)
                .retrieve()
                .bodyToFlux(String.class)          // WebFlux 自动按 SSE 拆行并去掉 "data:" 前缀
                .takeUntil("[DONE]"::equals)
                .filter(line -> !"[DONE]".equals(line))
                .concatMap(this::toFrontendEvents)
                .concatWithValues("[DONE]")        // 最后发 data: [DONE]
                .onErrorResume(e ->
                        Flux.just("{\"error\": \"请求上游失败: " + e.getMessage() + "\"}", "[DONE]"));
    }

    private Flux<String> toFrontendEvents(String chunkJson) {
        try {
            JsonNode delta = mapper.readTree(chunkJson).path("choices").path(0).path("delta");
            List<String> out = new ArrayList<>();
            String reasoning = delta.path("reasoning_content").asText("");
            String content = delta.path("content").asText("");
            if (!reasoning.isEmpty())
                out.add(mapper.writeValueAsString(Map.of("reasoning", reasoning)));
            if (!content.isEmpty())
                out.add(mapper.writeValueAsString(Map.of("content", content)));
            return Flux.fromIterable(out);
        } catch (JsonProcessingException e) {
            return Flux.empty();   // 忽略无法解析的 chunk
        }
    }
}
```

> `produces = TEXT_EVENT_STREAM_VALUE` 时，Spring 会自动给每个元素加 `data: ` 前缀和空行，与本契约格式一致。

### 静态页面

把本仓库的 `static/index.html` 放到 Spring Boot 的 `src/main/resources/static/index.html`，访问 `http://localhost:8080/index.html` 即可直接使用（页面用相对路径 `/api/chat`，无跨域问题）。

若前后端分离部署（不同域名/端口），需在 Java 侧加 CORS：

```java
@Bean
public WebFluxConfigurer corsConfigurer() {
    return new WebFluxConfigurer() {
        @Override
        public void addCorsMappings(CorsRegistry registry) {
            registry.addMapping("/api/**").allowedOrigins("*").allowedMethods("POST");
        }
    };
}
```

## 四、对接/替换步骤清单

1. Java 后端按第三节实现 `POST /api/chat`（路径、请求体、SSE 事件格式保持一致）。
2. 配好环境变量 `UPSTREAM_API_KEY`（不要把 key 硬编码进代码库）。
3. 用第一节的 curl 命令自测，确认能看到 `reasoning` / `content` / `[DONE]` 事件。
4. 把 `static/index.html` 部署到 Java 服务（或独立部署并配 CORS）。
5. 浏览器打开页面测试多轮对话与 Markdown 流式渲染。
6. 确认无误后即可下线 Python 服务，前端零改动。
